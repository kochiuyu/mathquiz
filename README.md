### Marking and variation

The [3ME1 scheme](https://bca.hkeaa.edu.hk/web/Common/res/2026priMarking/P3/TSA2026_3ME1_MS.pdf) distinguishes method, answer and presentation in designated problems, accepts other correct methods, and allows a range of valid responses in an open number blank. MathQuiz should record these dimensions in teacher rubrics. An automatically checked final answer should report the evidence it actually scores. New open-response families need a predicate for valid answers, with boundary checks, rather than one stored model answer.

The [3ME2 scheme](https://bca.hkeaa.edu.hk/web/Common/res/2026priMarking/P3/TSA2026_3ME2_MS.pdf) accepts equivalent fraction forms in a particular item and gives separate guidance for chart titles and construction. Review answer policies by task. Keep the existing pictured-count contract for `frac3a`; use a new family when equivalent-value acceptance changes the task.

The [3ME3 scheme](https://bca.hkeaa.edu.hk/web/Common/res/2026priMarking/P3/TSA2026_3ME3_MS.pdf) requires all relevant selections for some classification answers and accepts suitable alternative chart titles. Test omitted and extra selections separately. Give teachers a semantic checklist for titles and an example of an acceptable alternative.

3. Build an original mixed P3 diagnostic from reviewed tasks. Use its results to direct a pupil to the relevant skill practice. Record correct, incorrect and unanswered responses, and teacher review where needed. Validate timing with pupils before assigning a completion-time claim.
4. Add simpler P1 and P2 versions at their own curriculum limits. Use fewer objects, shorter wording and concrete representations. Check each against its EDB objective before release.
5. Verify both languages, phone controls, printed answer space, keys, rubrics, equivalent responses and older links. Track these as assessment improvements separately from the existing curriculum resource-completion count.

Use original contexts, values and diagrams for new MathQuiz items, with source references in author briefs. Preserve the official papers as linked references. Keep practical, oral and inquiry work in the full curriculum alongside these written assessment formats.

Use this order when two pieces of work compete for time.

| Priority | When to choose it | What to ship |
|---|---|---|
| 1 · Correct a mathematical or marking error | A released question teaches an incorrect relationship, rejects a valid answer or disagrees with its paper key. | Fix the affected route, check older links and document which quizzes are affected. |
| 2 · Finish the current objective | Existing material almost covers an objective, or a missing prerequisite blocks the next unit. | The missing pupil action and its marking evidence. The first example is checking subtraction by addition in P1. |
| 3 · Open the next gap in the grade | The active unit has usable material and its outstanding objectives are recorded. | Start the next batch below. Give an untouched objective precedence over additional variants of an already assessed calculation. |
| 4 · Build support shared by several objectives | A specific task needs a drawing grid, instrument, oral script or teacher rubric. | Implement the simplest usable form with the first real task. Reuse it for later grades after checking their different limits. |

Work from P1 through P6. The batches below give the proposed development order; teachers can assign the finished materials in their own order. Release a usable objective as soon as it is ready. A blocked practical task stays visible in its unit brief while work continues on the next objective. Defer general interface changes, accounts and larger item counts when they do not close a curriculum gap.

## How to decide that a unit is complete

Keep one row per numbered objective in the unit brief. Record the EDB reference and limits, the action the pupil takes, the live family or printable activity, the answer rule or rubric, and the review outcome. A teacher should be able to follow the link and use the material in either language.

| Review outcome | Evidence required |
|---|---|
| Open | Identify the missing pupil task, representation, assessment mode or unverified requirement. |
| Covered online | Link a released task and worked answer. Check the objective's range, boundary cases and applicable representations across its variants. |
| Covered by teacher assessment | Link a usable activity or script, materials and marking criteria for oral work, construction, practical measurement or investigation. Identify what the teacher observes. |

Mark a unit complete when every objective has linked evidence and all applicable remarks have been checked. An explanation in the answer key, a proposed question or a note that a teacher must assess a skill can identify a gap. Each still needs a pupil task before it counts toward completion.

## Author, verify and hand off a release

1. Select the next open objective from the queue. In its brief, record the assessed action, permitted number range, exclusions, bilingual prompt, worked solution and a likely error worth addressing. Reuse an existing family if its task already supplies the evidence.

### Visual direction and reusable components

Build a calm classroom tool using the current cream-and-green identity. Use colour sparingly for actions and states; mathematical figures remain the focus.

- Define CSS variables in the screen layer [ui.css](ui.css), loaded after [quiz.css](quiz.css) for canvas, surface, text, muted text, border, primary action, focus, success and error. Starting candidates are the current cream `#f7f6ef`, near-white `#fffefa`, dark text `#20392f` and green `#215a48`; validate every actual foreground/background combination before adoption.
- Use the existing system font stack with Traditional Chinese fallbacks. Keep the serif wordmark, but use a consistent sans-serif hierarchy for UI and mathematical prompts. Target 17–18px body text, 20–24px pupil prompts and a responsive 28–40px page title. These are starting design values, not fixed sizes that prevent zoom.
- Use a 4/8/12/16/24/32/48px spacing scale, restrained borders, 8–12px corner radii and minimal shadows. Allow a wider teacher workspace, approximately 1200px maximum, while keeping pupil reading areas around 760px.
- Create shared primary/secondary/text actions, grade selectors, labelled inputs, resource cards, availability badges, filter chips, empty states, error messages, progress and result panels. Specify hover, focus, active, selected, disabled and loading states where applicable.
- Use text plus symbols for correct, incorrect and partial-credit states. Never rely on green/red alone. Icons supplement labels; they do not replace meaningful action names.
- Use approximately 640px and 1024px as initial layout breakpoints, then test content fit in both languages. Avoid fixed-height cards, truncated Chinese labels and tiny diagram text. Respect reduced-motion preferences and avoid decorative animation.
